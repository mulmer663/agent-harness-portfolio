요청: $ARGUMENTS

## 0. 선례 찾기

위키에서 비슷한 작업의 노트를 먼저 검색한다(`search_wiki`). 같은 함정에 빠진 기록이 있으면 계획에 반영한다.

## 1. 설계 — planner

planner 서브에이전트에게 요청과 선례를 넘긴다. 받는 것:
- 목표를 한 문장으로 다시 적은 것
- 영향받는 파일과 단계별 계획
- 테스트 케이스 목록(정상·경계·실패)
- 위험과 아직 정하지 못한 것

계획을 사용자에게 보여 주고 승인을 받는다. 승인 전에는 코드를 고치지 않는다.

## 2. 구현 — 메인 에이전트

계획대로 구현하고 커밋한다. 계획에서 벗어나야 하면 이유를 적고 사용자에게 알린다.

## 3. 테스트 — tester

tester 서브에이전트에게는 planner의 테스트 케이스 목록과 변경 범위만 넘긴다. 구현하면서 한 추론은 넘기지 않는다.
같은 맥락에서 테스트를 짜면 구현의 오해가 테스트에도 그대로 들어가기 때문이다.
받는 것: 추가한 테스트, 실제로 실행된 태스크와 건수, 놓쳤을 수 있는 경우.

## 4. 리뷰 — reviewer

reviewer 서브에이전트에게 diff를 넘긴다. 지적은 요약하지 않고 그대로 사용자에게 전한다.
지적을 반영해 실행 동작이 바뀌는 커밋을 더 했으면, 그 커밋까지 다시 리뷰받는다.

## 5. 병합

결과(테스트 실행 내역, 리뷰 판정)를 보고하고 사용자의 병합 승인을 받는다.
